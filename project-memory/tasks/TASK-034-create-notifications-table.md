# TASK-034

# Create Notifications Table

## OBJECTIVE

Create the `notifications` table in PostgreSQL that stores user notifications for the platform. Notifications are generated by system events such as pipeline completion, outfit recommendations, and reminders.

## CONTEXT FILES

- `backend/src/database/migrations/`
- `backend/src/database/migrations/20260525_000001_create_users_table.sql`
- `backend/prisma/schema.prisma`

## ALLOWED FILES

- `backend/src/database/migrations/*.sql` (new migration file)
- `backend/prisma/schema.prisma`

## FORBIDDEN FILES

- Any file in `frontend/`
- Any file in `ai/`
- Any TypeScript source files except Prisma schema

## REQUIREMENTS

1. Create a migration file `20260525_000034_create_notifications_table.sql`.

2. The `notifications` table must have these columns:
   - `id` UUID, PRIMARY KEY, DEFAULT `gen_random_uuid()`
   - `user_id` UUID, NOT NULL, REFERENCES `users(id)` ON DELETE CASCADE
   - `type` VARCHAR(50), NOT NULL — values: `pipeline_complete`, `pipeline_failed`, `outfit_recommended`, `daily_reminder`, `laundry_reminder`, `system`
   - `title` VARCHAR(200), NOT NULL
   - `body` TEXT, nullable
   - `data` JSONB, nullable — arbitrary payload data
   - `is_read` BOOLEAN, NOT NULL, DEFAULT `false`
   - `read_at` TIMESTAMP WITH TIME ZONE, nullable
   - `created_at` TIMESTAMP WITH TIME ZONE, NOT NULL, DEFAULT `NOW()`

3. Create indexes:
   - `idx_notifications_user_unread` on `(user_id)` WHERE `is_read = false` — for unread count queries
   - `idx_notifications_user_created` on `(user_id, created_at DESC)` — for listing notifications
   - `idx_notifications_type` on `type` — for filtering by type

4. Enable RLS with policies:
   - `notifications_select_own`: SELECT WHERE `user_id = current_user_id()`
   - `notifications_update_own`: UPDATE WHERE `user_id = current_user_id()`
   - `notifications_insert_system`: INSERT with check (system role)
   - `notifications_delete_own`: DELETE WHERE `user_id = current_user_id()`

## ACCEPTANCE CRITERIA

- `\d notifications` shows all columns with correct types.
- The `type` column accepts any of the specified values.
- `is_read` defaults to `false`.
- `read_at` is `NULL` when `is_read` is `false`.
- Indexes are created for unread count and listing queries.
- RLS policies are enforced.
- JSONB `data` column stores arbitrary structured data.

## EDGE CASES

- `type` is VARCHAR(50) rather than an enum to allow future notification types without migrations.
- `data` JSONB column stores metadata like `{ garment_id, outfit_id, pipeline_id }` for actionable notifications.
- `is_read` and `read_at` should be updated atomically together.
- Notifications should auto-expire after 90 days (application-level cleanup job, not DB trigger).
- No UNIQUE constraint needed — duplicate notifications are allowed (e.g., multiple reminders).
